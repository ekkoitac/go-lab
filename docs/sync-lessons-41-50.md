# 第 41–50 题：逐题同步实验与帮助

依据用户提供的《学习：知识点教学中的交互与呈现方式》重新设计。十题各由一个独立 subagent 实现，主入口仅负责按题号懒加载，模型、视图和样式按题隔离。

| 题目 | 核心理解 | 操作与可见证据 |
|---|---|---|
| 41 | 启动、完成与进程退出 | 自主安排主任务与后台任务，比较回执与提前返回 |
| 42 | 并发与并行 | 分配执行单元和任务时间片，检查交错与同时执行 |
| 43 | 数据竞争与丢失更新 | 安排读、算、写，观察本地快照和共享值，比较同步边界 |
| 44 | 锁保护不变量 | 在转账中间插入读取，验证账户整体一致性 |
| 45 | 同步对象身份 | 对照复制锁与共享锁，看谁真正保护同一数据 |
| 46 | 等待环与锁顺序 | 构造持有与等待关系，回退改序，运行验证修复 |
| 47 | 读锁升级与复查 | 构造升级阻塞，在释放读锁后插入其他写者 |
| 48 | 登记与等待 | 调整 Add、启动、Done、Wait 顺序，观察计数与返回 |
| 49 | 初始化与每次业务 | 分离 Once 函数体与业务，观察后续调用是否执行 |
| 50 | 单字段原子与整体快照 | 在两次更新间读取，比较混合版本和整体发布 |

四个帮助入口分别提供情境映射、关系视图、分步机制和预测练习；帮助视图不嵌套完整主实验，不写入独立掌握记录。模型是显式约束下的教学调度，不能当作 Go 调度、公平性或性能保证。真实代码编辑器及正式复测继续由既有学习流程管理。

## 验证

- `npx tsx --test tests/sync-lesson*.test.ts`：逐题模型边界与修复语义。
- `npx playwright test tests/browser/sync-lab.spec.ts tests/browser/sync-diagram.spec.ts`：四类帮助、编辑器/掌握记录隔离、320/390px 布局和具体操作回归。
- `npm run build`：类型、课程完整性及生产构建。

浏览器测试使用独立的 `GO100_E2E_WEB_PORT`、`GO100_E2E_API_PORT`、`GO100_E2E_DATA_DIR` 和 `GO100_E2E_OUTPUT_DIR`，默认关闭 trace。

语义依据：[sync](https://pkg.go.dev/sync)、[sync/atomic](https://pkg.go.dev/sync/atomic)、[Go 内存模型](https://go.dev/ref/mem)。
