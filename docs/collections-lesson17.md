# 第 17 题：小切片保留大内存

依据用户指定《学习-知识点教学中的交互与呈现方式》，围绕“可达关系与容量边界不同”组织模型。

- 学习目标：能沿完整引用链判断原数组是否具备回收条件，区分限 cap、独立复制与移除其他引用，并说明复制成本。
- 典型误解：cap=2 意味分配仅有 2 字节；复制后立刻回收原数组；删除原变量就删除所有别名。
- 呈现形式：根引用到数组的关系图、小窗口与其余载荷条、可达逻辑字节和复制量指标、当前操作代码。
- 动手观察：调整原数组与小窗口大小；选择限容量、复制、增删别名、删除原引用；先提交可达性与依据再执行。不可执行的操作显示当前不适用并禁用执行。支持单步回退、从旧状态分叉、重置。同一初始条件下对照仅限容量与独立复制。
- 举例子：选择书签或复印页，控制同事的书签，主动构造“复制仍保留原书”的反例。
- 画图：独立构建假想存活引用图，开关两个根、选择 token 指向 A/B；重新计算可达性。明确它是静态图构建，不是假装程序可复活已释放对象。
- 拆步骤：另一别名始终存在的修复流程，依次复制、删除原引用、删除别名；逐步回退查看最后一条边的作用。
- 让我试试：图片头、网络魔数、文件索引三个新情境；先填写预测和理由才能揭示结果。揭示前 data-state 不包含 result。练习不写正式掌握状态。
- 边界：仅记录逻辑有效载荷，不模拟实际堆或 GC；cap 不作为分配大小；不可达仅为具备回收条件，不说已释放；真实编译器存活性可能早于赋 nil。使用非空 byte 窗口避免零长度指针边界。
- 可访问性：原生按钮、select、复选框、textarea、fieldset；状态提示 aria-live；键盘焦点；320/390px 换行；reduced-motion 禁动画。

验证：专属纯模型测试覆盖限容量保留、独立复制成本、别名阻止回收、回退分叉、受控对照及迁移题；专属浏览器用例覆盖操作路径、四类帮助、预测门槛、主实验不被帮助修改、窄屏和键盘。
