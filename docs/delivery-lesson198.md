# 第198题交互设计

- 学习目标：以实际制品身份连接部署与构建证据，区分内容身份、来源记录、可信来源和可重复构建。
- 主实验：构建 A → 部署 A → 同提交但输入不同地构建 B → latest 覆盖为 B → 根据保存的部署证据调查。控制摘要绑定、记录完整性、未提交修改和证明信任来源。预测及理由在首次单步后锁定，回退保留预测，重置开始新实验。
- 因果反馈：标签移动不部署内容；部署记录缺少摘要造成 A/B 歧义；有摘要而无输入记录只能确定内容；有记录而无可信构建者验证不能建立可信来源；所有方案都未执行受控重建，不能证明复现。
- 模型边界：artifact-A/B 是教学内容身份符号，不是简易哈希或真实 SHA。可信签名选项显式属于模型假设。dirty 仅标识未提交状态；恢复源输入还需要源码快照。固定公开输入，无秘密。保留两份制品，不代表实际仓库一定保留所有历史。
- example：cgo 构建差异的证据分类与收集，区分原因证据和内容差异证据。
- diagram：以内容、输入、可信度三个调查问题选择路径，联动关系节点与语义连线。
- steps：按前置依赖自主构造构建发布证据链，错误顺序被拒绝，可以撤回。
- try：对第三方签名者不可信的新情境先判断并说明理由，提交后锁定并揭晓；帮助练习不计独立掌握。
- 自动化契约：主组件无参默认导出；具名 Help({mode})，mode 为 example/diagram/steps/try。主根 delivery-lab-198，模型 live-model 的 data-state 包含状态、调查结果和 predictionLocked。操作按钮 data-delivery-action=step/back/reset；单步需先填写预测与非空理由。帮助根 delivery-help-198。
- 验证：8 个模型测试通过，目标 TSX/模型/测试局部 strict TypeScript 检查通过。320px 使用可收缩网格和折行控件，最终浏览器验证由集成任务执行。
