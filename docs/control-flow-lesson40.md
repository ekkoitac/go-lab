# 第 40 题：错误处理层级

| 设计项 | 实现 |
|---|---|
| 学习目标 | 为层级分配日志、包装和重试责任，区分重复报告与独立失败 |
| 典型误解 | 每层必须 log；重复传播就是多个独立失败；重试预算只相加 |
| 核心关系 | 向下调用、向上返回、责任边界与副作用计数 |
| 动手观察 | 每层开关日志/包装，选择总尝试1–3次，独立失败1–3个，单步/回退/修复 |
| 呈现形式 | 三层节点、调用/错误返回箭头、实际访问/日志/审计/响应计数与错误上下文 |
| example | 每层2次总尝试与边界3次总尝试对照，保持根因与包装语义 |
| diagram | 点击层级编辑责任，重新运行查看记录数量和上下文 |
| steps | 每步标出责任层与具体行为，保留记录证据、可回退 |
| try | 批处理新情境先预测诊断数、访问数并解释，提交后验证 |
| 模型边界 | 所有尝试失败；总尝试含初次；各层自身预算耗尽才记录并返回 |
| 重试计数 | 实际访问 = 请求数 × HTTP预算 × 服务预算 × 存储预算 |
| 日志计数 | 全部层启用时每请求诊断 = HTTP预算×服务预算 + HTTP预算 + 1 |
| 审计边界 | 每独立请求一个访问审计事件，与故障诊断分列，不按重复报告删除 |
| 质量目标 | 保留根因、操作上下文与边界响应；少日志不等于充分处理 |
| 证据边界 | 辅助迁移不写成绩；预测与理由先提交，理由自查 |
| 可访问性 | 浅色、键盘表单、aria-live、320/390px堆叠、reduced-motion |
