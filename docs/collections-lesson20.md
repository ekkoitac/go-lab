# 第 20 题：map 遍历与并发边界

依据用户指定《学习-知识点教学中的交互与呈现方式》设计：将呈现形式（键目录、分数表、读写路径、时间线）与交互（调度构造、预测验证、诊断修复、反事实对照）区分。

- 主实验：选择同步协议、键/整数键值快照、合法遍历次序、有无写者；自行构造读取、排序、写入、解锁、输出序列。每次动作先预测并填写理由，反馈到具体访问和锁，允许回退及重置。变更条件恢复基线。
- 举例子：目录/照片的类比，通过同一写入事件对照键快照与值快照，独立切换排序。
- 画图：搭建读者、写者经过同一 RWMutex 的访问路径，关闭写者以验证只读边界。
- 拆步骤：单步执行读锁、排序、阻塞写者、输出解锁、写者重试；支持倒放。
- 让我试试：配置导出、在线积分榜、冻结目录三种迁移情境。先判断次序与并发两个性质并填写理由，提交前不在 DOM data-state 揭示答案。不调用正式进度接口。

## 模型边界

教学模型将 map 读取表示为一个访问区间，并将后台写者放入该区间，检查同步协议能否排斥潜在重叠；不是真实 Go 调度或竞态检测器。未同步的冲突路径停止给出确定输出，不宣称一定 panic。区间外一次无重叠的观察也不能证明协议安全。使用同一 RWMutex 时，解锁后按目录读取值会再次取得读锁，所以是安全读取当前值，不是旧值快照。键集合并未模拟增删，后台只更新 amy 整数值。

预设遍历顺序只是语言允许的示例，不表示等概率，也不承诺每次不同。排序只建立次序，不建立读写同步。没有写者的只读情况假设 map 已安全发布。整数值副本可独立读取，指针/引用元素的深复制不在模型范围内。

## 验证

`npx tsx --test tests/collections-lesson20.test.ts` 验证排序、未同步访问、同锁阻塞、键与值快照、只读边界和不可变回退。专属 Playwright 用例覆盖主实验修复、四类帮助、隐藏迁移答案、状态保留、键盘以及 320/390px 和 reduced-motion；由根任务统一运行。
