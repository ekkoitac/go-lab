依据用户指定的《学习：知识点教学中的交互与呈现方式》，逐题先明确认知目标，再选择模型、呈现和任务。每题由一个独立 subagent 实现；共享层只负责按题号加载。

| 题号 | 核心理解 | 可操作模型与可见证据 |
| --- | --- | --- |
| 131 | 全局容量预算不同于单池配置和延迟保证 | 副本、surge、预留与单池调参；池卡片、容量条、本地等待 |
| 132 | 版本递增本身不能阻止旧数据覆盖 | 两人提交次序、CAS、冲突重读合并；草稿、影响行数、共享记录 |
| 133 | 事务边界覆盖业务不变量 | 同一 Tx、各自提交、逃出 Tx 对照；草稿、已提交余额、未知提交结果 |

## 辅助理解与证据边界

四类帮助分别负责情境对照、关系追踪、步骤证据和新情境尝试。帮助不复用主实验的状态；自由探索、已揭晓反馈和辅助练习不产生正式作答或独立掌握记录。原有帮助使用记录仍由应用保存。

每个模型提供预测和理由、可读反馈、回看和重置。模拟的资源量与时间来自明确的教学假设，不当作数据库运行、吞吐或 P99 实测。真实隔离级别、提交不确定性和跨系统崩溃窗口需在目标系统验证。

第 134 题的快照规则核对 [PostgreSQL 事务隔离文档](https://www.postgresql.org/docs/current/transaction-iso.html)；第 131 题单个 sql.DB 的池限制核对 [Go 连接管理文档](https://go.dev/doc/database/manage-connections)。各题更详细的模型限制见相邻 database-lessonNNN.md。
