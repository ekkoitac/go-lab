# 第 147 题：确认责任交接实验

## 学习目标与误解

让学习者区分 broker 的未确认记录、消费者发出的 ack、数据库持久结果。暴露三个误解：收到即确认仍能可靠重试、提交后确认就不会重复、发送确认等于 broker 收到确认。

## 呈现与交互

- 三栏协议状态板呈现 broker / 消费者 / 数据库，持久券数与未确认记录同步变化。
- 学习者设置确认时机、首次故障、同事务幂等；先提交 0/1/2 张券的预测和理由，再单步执行、回退或重置。
- 八个状态分别展示投递、提前确认、提交、后置确认、断连重入队、重投副作用、恢复确认，反馈明确指出哪一步失去恢复依据或产生重复。
- 四种帮助：签收单类比改变时机；双路径图注入同一故障并切换幂等；协议回放追踪提交失败；确认丢失练习预测并修复重复。

## 模型边界

单事件、单消费者、手动 ack；仅首次尝试注入一个故障。ack 丢失不会立即重投，等待 broker 检测连接关闭后重新入队。数据库已提交效果不会因断连回滚。重投阶段压缩为成功处理和确认，不重复注入故障；幂等与发券同库原子提交、记录不清理。没有模拟 broker 部署持久性、真实网络时间、并发或 prefetch，但提示生产需要限制未确认数量和重试预算。

所有预测与操作仅为 React 局部练习状态，不写正式掌握记录。data-state 明确分开 physical、config、prediction。

## 集成与校验

index.tsx 默认导出无 props Lab，命名导出 Help({mode})，支持 example / diagram / steps / try。测试根为 cache-message-lab-147 / cache-message-help-147；主状态 live-model；主按钮 data-cm-action 为 step / back / reset。

纯模型测试覆盖提前确认丢失、失败后重投、发送/收到确认区别、提交后崩溃重复、完整策略故障矩阵、状态不变量、预测隔离及回退重置。CSS 在窄屏采用单列，无固定最小宽；原生 label/select/checkbox/button 支持键盘，反馈使用 aria-live。
