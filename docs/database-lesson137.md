# 第 137 题：读己之写

- 学习目标：区分主库提交、复制应用、请求最低位点；解释等待超时与路由的关系，构造固定时长策略失效的长尾反例。
- 呈现形式：节点与复制关系、模型时钟、带时间戳事件证据；数据都来自独立纯函数 `trace`。
- 交互方式：操控复制延迟、请求到达时刻、等待预算或固定窗口，选择请求承诺与路由；先记录预测和理由，再单步提交、读取、返回；支持回退和重置。改变条件会清除预测，避免旧答案套用新条件。
- 路由：立即副本、主库、等待位点超时回主、等待位点超时失败、固定 sleep、固定粘主窗口。列表独立使用副本，详情要求至少本次写入位点。
- 帮助：example 为正常复制和长尾复制对照；diagram 为可切换请求的真实 SVG 位点关系图；steps 为可以逐步推进的位点证据链；try 换成头像长尾复制情境，并明确不计正式掌握成绩。
- 模型假设：一次写入、单主单副本、主库可用、读与网络耗时为零；复制应用原子发生，截止时刻恰好应用视为达标。窗口从提交起计。没有宣称跨设备会话自动传位点，也没有无限期陈旧承诺。
- 测试覆盖：提交不等于副本应用、立即陈旧、主库新值、等位点边界、两种超时行为、固定 sleep 与粘主长尾反例、列表分流、零预算、纯函数确定性。
