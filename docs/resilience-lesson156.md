# 156 慢报表与订单连接隔离

依据指定交互与呈现方式文档，使用资源分配、诊断修复、对照比较、关联探索与预测验证。学习目标是理解隔离必须触及共享瓶颈，以及保护收益与报表等待/闲置份额的权衡。

模型总连接预算为 6；6 个报表先到、下一拍 3 个订单到。报表持有连接 4 拍，订单 1 拍。每拍先推进已有任务并释放，再按队列顺序分配。共享模式与仅拆 HTTP 路由模式行为相同。配额隔离按业务连接数限制，订单份额 1–5，报表份额为剩余总预算，不允许借用。改配额不抢占已经运行的任务，已有超额连接先排空。主实验支持任意时点改策略、回退、保留配置重新运行与恢复共享基线。

视图展示实际任务标识、剩余工作、等待队列、完成量、空闲连接和累计请求等待拍数，反馈指出释放、获取与阻塞原因。example 同步对照共享与配额；diagram 追踪业务路径并高亮模型中对应队列/连接；steps 直接操作同一个真实状态转移模型；try 使用无订单的夜间导出情境，先预测和填写理由，再运行模型揭晓，明确不计入掌握成绩。

简化边界：单任务单连接、确定性执行时间、无取消超时、无跨池借用。数据库 CPU、锁和 I/O 未模拟，分连接池不保证这些资源已隔离。

验证：模型测试覆盖路由无隔离、订单保护、报表代价、非抢占修复、总预算不变量、空闲预留与纯状态快照。浏览器规格验证 390px、键盘操作、配额重跑、回退与页面无横向溢出，由主任务集成后运行。
