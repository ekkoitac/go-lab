# 第 133 题：同库转账事务边界

依据用户《学习-知识点教学中的交互与呈现方式》，先明确因果目标，再组合对照实验、参数操控、预测验证与单步回放。

## 目标与典型误解

理解业务不变量决定事务边界；仓储方法分别“用了事务”不等于整笔转账原子。全局 DB.Exec 的写入不属于已有 Tx；Commit 错误不等于确定失败或确定回滚。

## 动手观察

固定初始 A=100、B=20，可调金额 1–100，选择正常、第二笔失败或最终提交确认丢失。三种接线用完全相同输入同步演示：仓储各自提交、用例共享 Tx、扣款误用全局 DB。

先选择一个接线作为预测对象，再提交最终结果预测和理由；开始后冻结答案。参数改变清空预测，回退和重置支持修正思路。五个阶段显示调用位置、已提交余额、未提交草稿、总额变化及失败原因。回退是教学回放，不是真实撤销。

纯函数 snapshot 按参数和阶段推导状态。正常路径两笔都成功不证明边界正确；失败路径显示总额缺口。提交确认丢失将 committed 置空并保存两个可能结果，界面显示问号与待核对，而不是把本地旧值当数据库实值。共享 Tx 的两个可能结果总额均 120，但转账是否发生仍未知；应以稳定业务键核对。

## 四种帮助

- 例子：待盖章转账单，调整金额并单步看草稿被丢弃。
- 关系图：切换扣款执行者，实时改变 Tx 回滚边界及最后余额。
- 步骤：独立五步正常转账，代码、草稿与账本同步变化。
- 新题尝试：转 45 元、入账失败，选择接线并填写理由才揭晓运行结果；可修改重新验证。

帮助练习与正式测验分离，不写正式成绩或任何持久化学习记录。

## 限制和验证

同库、无并发、无手续费、无锁等待；逃逸 DB 操作假定取得独立连接并成功。模型不证明数据库隔离级别、真实驱动提交语义或恢复流程。草稿只呈现当前事务负责的写入（非共享路径的 A 显示横线，避免误认归属）。

CSS 使用 d133 命名空间；控件使用原生 button/select/range/textarea，支持键盘和 focus-visible；窄屏卡片堆叠避免固定宽度。live-model 的 data-state 用于真实状态验收。模型测试覆盖失败后的资金不变量、全局 DB 逃逸、提交不确定性、成功路径的中间可见性、所有合法金额及回放确定性。
