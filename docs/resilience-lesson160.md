# 第 160 题：按窗口证据恢复流量

目标：区分就绪与冷态容量；解释预热与线上请求的资源竞争；观察放量后的排队与失败，凭证据暂停、回退，再尝试更高权重。

## 模型与交互

- 单位为千次 / 观察窗口；入口固定 50。冷容量可选 5、30、60，上限 60。
- 预热预算先占用当窗容量，剩余用于旧队列与新流量；最多留下 10 千次排队，其他请求失败。每窗严格满足：旧队列 + 新流量 = 有效完成 + 失败 + 新队列。
- 无积压时，预热每单位带来下窗 2 单位容量，线上每完成 5 单位带来 1 单位容量；过载不增长。这是明示的确定性教学近似，不是容量预测器。
- 连续两个有积压或失败的窗口触发一窗口剔除；剔除窗口清退队列，下一窗口原权重重入。入口未分配给本实例的流量单独列示，不当成本实例业务成功。
- 连续两次有真实流量且无积压、无失败允许增加 10% 权重；配置变化清空证据。门槛只证明当前档位，不能保证下一档。
- 操作历史包含配置和窗口快照，允许回退；回退健康档位保留积压，因此修复须重新采样，不能用按钮伪造恢复。
- 默认瞬时全量可复现过载—剔除—原权重重入的循环。冷容量 60 时，全量可以健康，表达策略的适用边界。
- 不模拟请求延迟分布，不制造 P99；真实系统仍要观测延迟及依赖指标。

## 四种帮助

1. 举例子：同步推进同样冷容量、预热预算、入口的 100% 与 4% 两条轨迹，仅权重不同；提示低权重健康并不等于整体恢复。
2. 画图：固定容量与流量，只调整预热预算；公式与三段因果链、有效完成、排队及下窗容量同步更新。
3. 拆步骤：扮演恢复控制器，在每档两次健康证据后自行放量，恶化时回退。
4. 让我试试：三个新容量情境，提交预测和理由后才能运行揭晓；切换清除辅助练习状态，不写正式成绩。
