# 第 184 题：两道字节预算实验台

本模块依据《学习-知识点教学中的交互与呈现方式》实现，围绕“证据来自实际消费，而不是长度声明”设计参数操控、同条件对照、预测验证、单步与回退。

## 学习目标与可检验误解

- 读满 N 不等于源流已经结束：只读 N 的 EOF 可能来自限额。
- N+1 为探测上限；恰好 N 且接下来是真实 EOF 可以接受，出现额外字节即拒绝并丢弃暂存。
- Content-Length 仅提前拒绝明显超额；未知长度和较小声明仍进入实际读取。
- 上传压缩字节、实际解压总量、条目数、路径及链接约束必须分别检查。

## 动手观察

同一输入驱动 N 与 N+1 两列读取器。先选择最终结果并填写理由，才能单步执行。每次至多消费一个字节，列内显示实际读取量、解压量、条目计数、业务返回量与当步原因。完成后比较预测；回退恢复上一个确定性快照，重置清除预测。改变输入自动开始新实验。

预设覆盖未知长度 5 字节、恰好 4 字节、空输入、2→10 压缩扩张、3 个小条目、父目录路径、链接。上传和解压预算独立可调；N=0 可检验空输入与一个字节。

归档的 N-only 分支若截断，会由教学格式完整性检查拒绝，不把截断的压缩包假装为完整归档继续展开。

## 换个方式理解

- 举例子：操控包裹队列与仓库容量，让两位检查员验收；库容与临时探测位置分离。
- 画图：操控上传和解压预算、路径，观察通过或拒绝迁移到哪道闸门，后续计数是否仍为零。
- 拆步骤：从恰好 N 的输入开始，先预测再逐字节读取，保留完整回退与重置。
- 让我试试：新音频流、备份导入及零上限情境。先输入预测与理由才展示反馈，不预先显示答案。

四种帮助的 React 状态独立于主实验。模块不调用 progress、attempt 或 reveal，不产生课程掌握证据。父界面本身的帮助使用记录按原有机制处理。

## 模型范围

这是确定性小整数教学模型，单位为字节，不是字符数。输入及预算限制为 0–1024 的安全整数；UI 只给出小范围下拉值。网络分帧、压缩算法、CPU、时长、内存分配及文件系统操作不在模型内。Content-Length 与源流特意解耦，不模拟 HTTP 报文定界。

归档每条目的大小代表按步实际产出的字节总量，预算在消费时比较；既不是信任归档声明，也不先展开全部数据。模拟 N+1 探测可能消费预算之外的一个字节，超额后不向业务提交内容。

路径策略保守拒绝根路径、盘符、父目录段和所有链接；这不是生产安全解包实现，不能替代格式解析、目标目录约束、文件系统竞态防护和暂存清理。图中源流总量是教学视角已知信息，读取器只有实际读取才获得证据。
