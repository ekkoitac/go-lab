# 第 142 题：更新数据库和缓存

学习目标：依据并发时序追踪旧值来源，解释“提交后失效”仍存在迟到回填，并区分删除失败与并发回填两个窗口。

- 动手观察：四个调度（先删后写、先提交后删的迟到读、删除失败、第二次删除后迟到）。先提交最终缓存预测和理由，再单步、回退、重置；缓存值、读者快照、数据库版本、版本门槛、重试责任与日志联动。
- 边界实验：仅比较现有缓存版本保护已有 v2，却无法在空缓存中识别 v1；保留失效门槛在本模型的原子更新假设下拒绝迟到旧读；先删后写仍只有旧门槛。TTL 从回填开始，允许推进到过期、再次回源。
- 四帮助：example 改读取时机的目录搬运类比；diagram 点击节点追踪证据并执行回填；steps 自行排序事件生成反例；try 报价 v7→v8 的保护选择、预测与理由。
- 所有状态局部保存，不写正式成绩。模型不连接真实数据库或 Redis，版本门槛不声称是 Redis 自带能力。生产协议需处理门槛原子更新、保留时长和失败恢复，不能推广到任意跨系统副作用。
- 可访问性：原生按钮/选择框/文本框，排序含键盘按钮，状态反馈，390px 与帮助窄栏纵向排布，reduced-motion。

验证：目标纯模型测试覆盖两个并发窗口、双删反例、空缓存版本边界、删除失败与重试、TTL 的回填起算、快照不可变及迁移输入。主代理统一执行类型检查及浏览器验证。

UI 操作：在主实验选“并发场景”，选“回填校验”，选择“我的预测”并填写“预测理由”，逐步点击 data-cm-action=step；结束后观察 live-model 的 data-state。帮助按 example/diagram/steps/try 进入独立局部状态。
