# 第 148 题：分类重试与死信

按用户指定的《学习-知识点教学中的交互与呈现方式》将学习目标、呈现形式和交互分开设计。

- 学习目标：解释永久错误为何不会因重试而消失；预测暂错在类型、预算与时间约束下的路由；区分隔离和恢复成功。
- 呈现：待处理、延迟、死信三泳道与已提交效果联动；每步显示时间、处理次数、无效工作及正常订单进度，失败说明显示具体因果。
- 主交互：设置策略/错误/尝试预算/依赖恢复/抖动 → 记录预测和理由 → 单步执行、回退、重置；通过死信修复与限速重放进行反事实干预。修改规则须回到初始状态，保证预测对应当前实验。
- 换个方式理解：例子使用分诊比喻并运行相同三步对照；图解用类型和预算构造分支并联动真实状态；步骤逐帧追踪暂错退避；试一试要求先预测和解释，再验证原样重放或修复重放。
- 可追踪性：保留事件 ID、原始载荷、原始版本、失败原因、时间和尝试次数；修复副本与不可变失败归档分离，重放不删除归档。相同事件完成后重复处理不再写入业务效果。
- 模型边界：单消费者，队首重入是本实验的调度假设；已配置可靠死信隔离通道，每步处理一条消息。固定抖动样本便于复现，不是生产随机化算法。明确暂错类型，不用字符串匹配推断分类。重放每三时间单位最多一条，不模拟 broker 网络、存储故障或多消费者。
- 掌握证据：预测与物理状态分开保存；所有帮助和实验仅保留组件局部状态，不写正式成绩。阅读提示后的表现不充当独立掌握。
- 无障碍：原生 label/select/textarea/button，显式焦点和禁用状态；窄屏泳道纵向排列，不依赖悬停、颜色或拖拽。
