# 第 139 题：可恢复分批导入

## 教学目标与交互

让学习者区分已读位置、事务草稿、持久记录和已提交断点，解释故障窗口为何导致跳过或重放。呈现形式是商品格子、并排状态表和有方向的关系图；实际交互包括单步执行、批量参数控制、崩溃注入、断点恢复、回退、预测与理由、错误协议修复。

默认使用同一份 8 条有序输入对照全量数据事务与每批 3 条；每批可改为 2/3/4 条。读入步骤只改变草稿与已读位置，提交步骤才改变持久数据。数据和断点同事务时一起提交；选择错误边界后，数据和断点分开持久化，可在两次提交之间崩溃。稳定业务键幂等消除重放重复记录，但无法填补先写断点造成的漏写。

## 可复核实验

- 默认执行 4 步：全量事务草稿 4 条，持久数据 0 条；有限批次已提交 3 条，断点 3。
- 断点先提交、每批 3 条：执行 4 步后崩溃并恢复，K1—K3 被跳过，展示断点前缺失。
- 数据先提交、每批 3 条：执行 4 步后崩溃并恢复，对比开启和关闭幂等的重复条数。
- 在原子提交前后任意崩溃：草稿丢失，已提交前缀保留，恢复依据断点而非原已读位置。

预测要求输入右侧下一步持久记录总数与理由，再执行下一步显示实际数量及具体模型事件。普通观察操作允许直接执行；帮助或已揭晓的实验均不写入正式成绩。

## 四类帮助

- example：5 条输入每批 2 条，观察已提交前缀与未提交草稿。
- diagram：实时有向输入 → 草稿 → 数据/断点 → 恢复起点关系；提交标签随协议变化。
- steps：最近六个真实状态快照及事件，列出已读位置、断点和持久记录作为证据。
- try：换成 7 条输入每批 3 条，或数据先提交的故障任务；修复按钮重置为同事务和稳定业务键，再运行验证。

## 模型边界

固定输入版本、固定顺序、稳定业务键；未模拟真实数据库锁、日志字节或时间。草稿峰值只衡量本模型同时持有的输入行数，不作为吞吐或实际占锁的证据。真实导入还需压测确定批量、限速、保存输入版本与失败行。分批允许已提交前缀对外可见，不提供全量原子可见；全部完成才可见需要暂存版本、校验与原子发布引用。

## 验证

纯状态模型测试覆盖默认对照、不同批量每一故障位置的原子恢复、断点先写漏项、数据先写重放及幂等差异、最后短批、崩溃/完成状态不再前进。CSS 全部限定 .db139，按钮与表单支持键盘及焦点提示，主视图窄屏单列，帮助栏使用独立窄栏布局。
