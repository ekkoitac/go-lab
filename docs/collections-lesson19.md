# 第 19 题：库存账本与两结果读取

依据用户指定《学习-知识点教学中的交互与呈现方式》，将学习目标设为区分业务值与存在性，并定位 nil map 的读写边界。

- 动手观察：库存账本与代码联动；A 初始为 0、B 缺失、C 为 8。每次查询先分别预测 value / ok 并说明理由，运行后显示差异与值来源。可新增/改值/删除、切 nil、make、回退与重置；每次操作展示账本前后状态。读取不会新增缺失键。
- 举例子：bool 配置表，可构造已有 false 与缺失 false 的反例。
- 画图：切换查询目标并删除/恢复 A，沿命中判断分别追踪值来源及存在性。
- 拆步骤：nil 写入 panic → 修改程序 make 并重启 → 重写零值 → 查询验证。明确不是从未处理 panic 自动继续。
- 让我试试：新配额数据与 nil/delete 情境；答案在先填数值、存在性、理由后揭示。与引导探索状态分离，不写正式成绩。

模型只使用单线程 map[string]int，库存控件范围 0–99；顺序仅供显示，ok 不代表同步。回退与逐步诊断是教学展开。原生表单/按钮支持键盘，局部 c19 样式使用浅色青绿配色，320/390px 自动折行，尊重 reduced-motion。

验证：独立模型单测覆盖缺失/零值、只读不插入、增删改、nil 安全读/delete、写入 panic、修复和不可变历史；专属浏览器测试覆盖主实验、四类帮助、答案隐藏、状态隔离、窄屏和键盘。浏览器与整体构建由主任务统一执行。
