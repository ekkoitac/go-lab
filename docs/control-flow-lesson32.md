# 第 32 题：循环变量与闭包

| 设计项 | 实现 |
| --- | --- |
| 学习目标 | 从声明位置推导回调引用的变量身份，区分登记时输入与执行时读值。 |
| 典型误解 | 闭包自动冻结值；新版 Go 让所有循环变量都独立；独立指针意味着深复制。 |
| 核心关系 | 变量身份、引用连线、登记与执行的时间顺序。 |
| 呈现形式 | Go 代码、引用图、三种方式的同时间对照、实际输出。 |
| 交互任务 | 修改 2–4 个整数；逐一登记；结束循环；逐一调用；回退；切换声明方式；点击回调追踪共享邻居。 |
| 模型与反馈 | 纯函数从输入和时间步重建变量及引用；执行读取当前变量；每一步交代哪个变量改变、哪些引用保持不变。 |
| 帮助方式 | example 是可点击商品按钮、查看错配并修复声明方式的诊断场景；diagram 专注已登记引用关联探索；steps 是可回退教程；try 是新输入先预测加理由后揭晓。 |
| 独立验证 | 帮助内练习不写入独立掌握；理由展示供证据自查，不声称自动评价。现有独立测验保持原状。 |

模型边界：Go 1.22+ 模块语言语义、整数、循环完成后串行调用，不模拟 goroutine 调度。显式参数用真实闭包工厂 makeFn(v)，参数在工厂调用时复制。独立变量不表示深复制引用对象。

键盘使用原生 button/input/select；过程消息 aria-live；引用图提供文本等价关系与可操作按钮；窄屏比较纵向堆叠；遵守 reduced-motion。

验证：node --import tsx --test tests/control-flow-lesson32.test.ts 检查共享身份、每轮身份、参数副本、分离登记执行、回退与输入边界。
