# 第 149 题教学设计

目标：区分生产／投递顺序与业务完成顺序；用稳定订单键和分区内串行消费守住每个订单的依赖，同时解释跨订单并行和热点键边界。

依据用户提供的《学习-知识点教学中的交互与呈现方式》：采用参数操控、对照比较、预测验证、诊断修复与举反例；呈现使用分区执行泳道、实际完成时间线、订单版本卡及指标联动。操作影响调度状态，而不是只翻说明文字。

主实验：四条预先入队事件，创建 3 拍，其余 1 拍。选择全局队列／稳定订单 ID／逐条轮转，再选择分区串行或双 worker 并发；可开原子版本前置检查、切换热点输入。填写结果预测与理由后单步推进，读队列、执行剩余拍数、完成日志、订单版本差异。每步有因果说明，支持回退与重置。错误路由或同分区并发会使付款先于创建完成；版本检查会拦住缺口并保留待恢复事件列表，不声称丢弃事件就完成处理。

四种帮助：example 对同一输入对照全局与按键耗时；diagram 可搭路由和执行边界并观察实际结果；steps 逐拍追踪稳定键串行方案；try 改变热点分布，先预测总拍数与理由再验证。帮助与主实验均仅保存在组件局部状态，不写正式掌握记录。正式独立迁移证据应来自未看帮助的新输入题。

模型假设：输入次序固定，分区 FIFO 派发；同拍完成的展示顺序由确定性遍历选定，不承诺跨分区顺序。串行容量 1，并行容量 2；不模拟网络、失败、重试、再均衡或生产性能。提交前置条件为 currentVersion = incomingVersion - 1，检查与写入原子；这比只检查 incomingVersion > currentVersion 更严格，因为这里的每个业务动作依赖前序。拒绝后需保留并恢复，本模型不自动重试。不从该实验外推多写者版本、全局约束或动态分区迁移策略。

接口：默认导出无 props Lab；命名 Help({mode}) 支持 example/diagram/steps/try。根测试 ID cache-message-lab-149 / cache-message-help-149。主状态 live-model 的 data-state 为 { config, physical, prediction }，预测与真实模型分开。主按钮 data-cm-action 为 step/back/reset。纯模型测试覆盖安全路由、异步乱序、错误分区、拒绝缺口保留证据、热点边界、全配置事件守恒、预测门控和回退。
