# 71–80：数据与边界交互设计

## 实现约束

每题由独立 subagent 实现，主代理整合与验收。每题拥有纯函数模型、主实验、三个帮助视图、局部 CSS、模型测试和浏览器测试。公共章节加载器只负责懒加载。

主实验提供引导预测、理由、单步、回退、重置、直接自由实验、保留基线和证据修正。条件变化开启新一轮；正式编辑器、题库、评分及数据库格式保持原有职责。模型结果不是实际数据库、文件系统或 shell 执行结果。

定制帮助名称映射到现有 diagram / steps / try 模式，继续使用原求助记录 API。帮助内练习区分首次、反馈后和提示后尝试，不写入正式答题与掌握记录。

## 逐题模型与边界

| 题号 | 可观察模型 | 主要边界 |
|---|---|---|
| 71 | 字段、编码规则、输出键的路线 | 三个普通 string 字段；显式排除敏感字段，空值省略不能证明永久排除 |
| 72 | 请求、解码目标、业务更新 | 缺失/null/0；新建与重用目标；null 清除是业务约定 |
| 73 | 原文、浮点表示、转换与范围检查 | 原文始终保留；BigInt 精确计算；仅十进制整数，不展示越界浮点转整数的伪确定结果 |
| 74 | 输入流、逻辑游标、两次 Decode | 有限配置预设；逐值扫描；未知字段检查不等于尾部检查 |
| 75 | 查询结构、数据槽、匹配结果 | 有限查询规则；绑定、标识符白名单和租户授权分别处理 |
| 76 | Rows 游标、返回路径、连接所有权 | 单结果集；EOF/遍历错误自动释放；Scan 错误与 Rows.Err 分离 |
| 77 | 已提交余额、事务内修改、执行时间线 | 有限余额快照；db 修改不受 tx 回滚；Commit 错误保持未知 |
| 78 | 连接槽、持有者、等待队列、统计值 | 容量不等于已开连接；教学 FIFO 不代表 Go 调度保证；时间是模拟时间 |
| 79 | 虚拟目录树与路径解析路线 | Windows/Unix 预设；词法检查与根范围解析独立；不访问真实文件 |
| 80 | HTML、日志、命令参数输出管线 | HTML 文本节点上下文；所有危险输入仅作文字或结构展示，不执行 |

三个帮助任务的标签集中在 `src/components/data-boundary-lab/help-options.ts`。各题默认导出无参数主实验，命名导出 `Help({mode})`。每题样式使用独立前缀，主实验/帮助测试根分别为 `data-boundary-lab-N` 与 `data-boundary-help-N`。

## 验证方式

- `npx tsx --test tests/data-boundary-*.test.ts`：模型与边界。
- `go run ./tests/fixtures/data-boundary-go/main.go`：真实标准库语义核对。
- `npm run build`：类型、内容完整性与生产构建。
- 浏览器专用测试：`tests/browser/data-boundary-*.spec.ts`，覆盖 1440px / 390px、键盘、减少动态效果、预测修正、帮助任务、可见状态变化及记录隔离。
- 浏览器使用独立端口、缓存、数据库和输出目录；共享工作区存在其他章节并行改动时，记录环境或其他章节失败，避免覆盖它们。

标准库 fixture 在 Windows amd64 / Go 1.26.1 上通过 46 项检查，覆盖字段标签、null 与复用、精度、流式解码尾部、Rows 生命周期、取消与池统计、词法路径和 HTML 文本编码。它不验证完整 SQL 引擎、数据库隔离或全部平台文件系统行为。
