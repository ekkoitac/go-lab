# 第 16 题：copy 不会分配长度

依据指定《学习：知识点教学中的交互与呈现方式》：学习目标是区分长度与容量，解释 min(len(dst), len(src))，确认整数独立复制与引用元素浅复制的边界。

## 动手观察

- 参数操控：源长度、目标长度、目标容量（0–8）；目标容量不能小于长度，增加长度时会同步满足合法容量。
- 预测验证：先提交数量与依据，再逐项展开复制并展示返回值；看过执行后保留原预测，回退不伪装成独立新答题。
- 多视图联动：Go 代码、两块存储、虚线容量格、当前写入项及返回值联动。
- 单步与回退：复制整数后修改目标首项，源值不变；支持精确回退和重置。
- 默认 dst 长度 0、容量 3，直接暴露典型误解。目标长度非零但源为空时仍可执行后续目标修改。

## 换个方式理解

- example：目标反推。为四张快照卡配置盒子数量与空间并运行验收，缺失数量给出修复依据。
- diagram：引用图与边界。复制 []*int 后区分解引用修改对象与替换目标指针槽；操作从共同基线开始。
- steps：重叠复制映射。选择左右搬移，单项展开、回退；根据调用前源值定义结果，明确不代表实际执行顺序或额外分配。
- try：三种新输入轮换；结果在提交数字与理由之前不进入 DOM 或 data-state；揭示后标为练习，不写正式掌握记录。

## 可访问性与模型范围

所有操作使用原生 button/select/input/textarea，支持键盘和可见焦点；反馈 aria-live；320/390px 控件换行；遵循 reduced-motion。逐格展开是教学视图，不表示 Go copy 可暂停或保证复制顺序。A/B 是逻辑存储标识。容量格不能直接通过 dst 索引访问。
