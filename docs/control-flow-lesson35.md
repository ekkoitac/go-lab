# 第35题：defer 后登记先执行

依据用户《学习-知识点教学中的交互与呈现方式.md》，通过可构造的登记顺序、可逆栈操作和资源变化建立因果理解。

| 设计项 | 本题设计 |
|---|---|
| 学习目标 | 预测 defer 执行顺序，按资源依赖安排 Flush、Close、Report；分清循环结束与当前函数返回。 |
| 典型误解 | 按希望执行顺序书写 defer；循环每轮清理；只要顺序正确就不会出错；延迟调用错误会自动被检查。 |
| 核心关系 | 登记先后与弹出逆序，Flush 对连接打开状态的依赖，收集结果的时间点。 |
| 呈现形式 | 可排序代码行、栈顶明确的纵向栈、缓冲/连接/写入资源图、错误和结果快照。 |
| 交互任务 | 上下移动三项登记语句；修改缓冲数量；注入写入失败；单步压栈/函数体运行；显式 return；逐项弹出；回退重置；对照相同输入下两种登记顺序。 |
| 模型反馈 | 纯函数不可变状态；每项弹出实际修改资源或记录错误；Close 之后 Flush 保留待写数据；Report 捕获当时结果；失败后仍执行后续 defer。 |
| 帮助方式 | example：穿脱层次操作类比；diagram：代码行与栈项双向选中，并映射弹出次序和资源依赖；steps：3轮循环逐步累积 Report，离开循环仍不清理，显式函数返回后逆序弹出；try：嵌套租约新情境先预测与理由，再揭示依赖结果。 |
| 独立验证 | 有帮助探索不写入成绩。迁移练习切换登记顺序清除预测和揭晓；既有独立测验继续承担掌握证据。 |

## 明确边界

栈属于当前函数调用，不属于整个 goroutine。循环演示使用 report(i) 显式参数，其轮次在登记时确定，避免与闭包捕获混淆。

资源模型是独立缓冲和连接，Close 不隐含 Flush。真实 API 依契约判断。错误集合是明确安排的处理，不是 Go 自动收集返回错误；本题不模拟 panic/recover。注入失败按零条写入简化，不模拟部分写入。重复 Close 在纯模型中是无状态变化，本题不推断真实库行为。

Report 先登记才能最后执行并取得完整结果；如果用户移到登记末尾，快照会早于资源清理，让错误安排有可见后果。

## 验证与可访问性

本题纯模型测试覆盖逆序弹出、压栈不执行、函数返回边界、三轮循环累积、成功和失败 Flush、错误后继续清理、过早报告、不可变历史重放、排序和非法输入。
