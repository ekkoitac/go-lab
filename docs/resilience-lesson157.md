# 157：降级契约

学习目标：把远端真实业务结果、本地证据与用户展示分开；用权威证据解释何时可从未知迁移到终态，明确推荐降级的时效或个性化损失。

## 动手观察

初始错误契约把 HTTP 200 映射为支付成功，远端默认未扣款。本地状态仍为未知，因此成功展示并不构成证据。单步依次执行超时、降级、核对；修复按钮回到相同超时点分叉，改为处理中并登记核对，收到渠道终态才更新本地状态。可切换远端已扣款、查询不可达、陈旧或缺省推荐。查询失败保持未知，不按超时时间制造失败事实。回退可逐步复核，重置保留当前配置，改变输入从头开始。

## 换个方式理解

- 示例：固定同一远端结果，并排推进错误与正确契约，比较相同 HTTP 200 下的证据、待核对和发货许可。
- 关系图：连接或断开交易号到权威凭证的核对路径，状态模型随连线改变；选择远端、本地、界面节点联动解释当前因果。
- 步骤：直接操作同一真实模型的超时、降级、核对步骤，可以回退与构造反例。
- 尝试：机票、头像、退款三种新场景，先提交契约判断与理由再揭晓；揭晓后修正不当作独立掌握，不写正式进度。

采用用户指定文档中的参数操控、对照比较、反事实干预、诊断修复、预测验证与证据推理；呈现形式使用状态节点、证据链与并排视图。每个视图围绕同一事实模型。

## 边界与验证

确定性教学模型，无真实支付。成功查询特指权威终态，不把暂时未找到交易等同未扣款；真实工程仍需幂等与人工核对策略。远端事实展示为实验上帝视角，用户请求处理程序不可偷读它。

模型测试覆盖两种远端事实、超时未知、HTTP 200 不证明成功、修复与核对证据、查询持续失败、推荐损失与状态快照独立。浏览器测试覆盖假成功修复、回退重置、查询失败、390px 和键盘。全部交互为原生按钮、select、checkbox、textarea，并支持 reduced-motion。
