# 第 14 题：append 的容量分支与隔离边界

依据用户指定《学习-知识点教学中的交互与呈现方式》设计，先定目标，再选择数组格、描述符和条件分支视图。

- 目标：预测容量分支、辨认元素共享与独立长度；区分限制容量和立即复制。
- 动手观察：容量 2–6 建立基线；自主追加或写入；预测并写理由才能验证。每次执行显示操作前后变化及原因，可逐步回退、重置。容量控制明确重开基线。
- 反事实：任一步可限制 b.cap 或分配新数组并 copy，再运行相同操作比较。
- 举例子：订单桌支持先换餐后追加、先追加后换餐，保留历史污染；座位数控制是否搬家。
- 画图：可调容量、插入三索引限制，追踪 append 前后的分支与引用归属。
- 拆步骤：逐步执行限制容量、已有元素写入、append、再次写入，证明限制不等于已有元素隔离。
- 让我试试：新情境 raw=[4,8,12]，三种预处理，分别发生追加前后写入；提交数值和理由后才揭晓结果，不调用成绩接口。
- 边界：只建模整数和从第 0 格开始的切片；分配示意采用 cap=新长度，明确不预测真实 Go 容量倍率；预留槽位是零值而非不存在；显示的数组编号是逻辑标识。
- 可访问性：原生 select/button/range/text input，明确 label、键盘操作、聚焦样式；320/390px 可换行，支持减少动画偏好。

实现文件：lesson14/index.tsx、model.ts、style.css。每个帮助模式均有独立状态；主模型公开 live-model/data-state。

验证：模型单测覆盖复用、分配、三索引前后共享、复制、历史不可恢复、同值写入、长度边界及新情境；浏览器测试覆盖关键路径、帮助隔离、答案隐藏、无成绩写入和移动布局。E2E 交由根任务统一执行。
