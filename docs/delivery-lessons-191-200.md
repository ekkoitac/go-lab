# 191–200 题：测试、交付与架构演进交互

依据用户指定的《学习：知识点教学中的交互与呈现方式》重新设计。每题由独立子代理实现，入口按题号懒加载；模型、帮助与样式分别归属于该题。

## 教学约束

- 先定义要解释的机制，再选择呈现形式和操作。流程图、时间线、矩阵是呈现形式；单步、调参、诊断、证据选择才是交互。
- 观察操作改变可检查的模型状态；显示变化原因，允许重置，过程型实验提供回退。
- 帮助的“举例子、画图、拆步骤、让我试试”分别承担具体情境、关系探索、过程拆解与新情境判断，不能只是同一实验换标题。
- “让我试试”在提交选择与理由后揭晓，并明确属于辅助练习。理由由学习者核对，不能把非空文本当成已证明理解。
- 模拟展示的是显式假设下的因果关系，不声称连接真实数据库、执行真实发布或测量生产性能。
- 保留原题内容、代码编辑器、决策草稿和正式测验记录。帮助与观察使用独立组件状态。

## 每题的具体交互

| 题号 | 动手观察 | 关键可检验证据 |
| --- | --- | --- |
| 191 | 注入支付缺陷，配置测试层与依赖，再修复对照 | 单测全绿仍可能遗漏重复支付；真实约束模型揭示提前发出的消息 |
| 192 | 同一写入交错下对照 map 与版本条件写，冲突后重读重试 | 两次“成功”是否保留两个增量；契约测试不等于真实服务验证 |
| 193 | 安排 worker 时隙，比较 sleep 与完成信号，注入漏关 done | 值已写入与同步证据不同；总预算用于失败兜底 |
| 194 | 扩展字段、捕获回填批次、注入并发改名、核验和收缩 | 旧版本回填会覆盖新值；旧读写者和回滚窗口仍阻止删列 |
| 195 | 在容量与客群约束下逐档放量、观测、暂停和回切 | CPU 正常仍可能金额错误；回切不会撤销已写订单 |
| 196 | 备份、迁移、新写、回滚、恢复、逐笔核账 | 备份后订单丢失、格式不兼容、总额相等但单笔错误 |
| 197 | 逐字段改共享对象，与候选校验后原子发布对照 | 非法值污染、半更新、旧请求快照保持、连接资源独立切换 |
| 198 | 构建 A、部署、构建 B、覆盖 latest、追溯 | 标签歧义、摘要绑定、来源信任与可复现分别需要什么证据 |
| 199 | 改变组织与成本，绑定证据、复核并发布替代 ADR | 旧记录不被覆盖；发布决定不会降低实测成本 |
| 200 | 相同负载下比较三条演进路线，核算成本后决定扩大或回退 | 修复热点与拆分的因果不同；硬隔离不能被性能收益抵消 |
