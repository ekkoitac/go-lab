# 第 18 题：nil 与空切片

依照用户《学习-知识点教学中的交互与呈现方式》：学习目标是区分元素数、nil 性质和协议约定，构造可交付的 JSON 输出。

- 动手观察：可修改切片、规范化策略和接收契约；内部切片、边界局部值、JSON 与接收结果联动。先提交预测和依据，再编码；失败后可诊断修复、回退、重置。
- 举例子：选择篮子状态与业务契约并验收，建立“没有元素”和“是否提供集合”的区分，说明业务含义非语言规定。
- 画图：直接干预边界管线，观察 nil 转为空数组；改为非空输入检查数据不被修复策略吞掉。
- 拆步骤：同起点对比 clear 与截短，逐步执行、回退、重放，清楚显示长度与元素变化。
- 让我试试：不同日志情境先预测并写依据，提交后揭晓；不写正式掌握记录，改变题目清除旧反馈。

模型仅表示 []int 常规 encoding/json 编码；不模拟地址、容量增长、GC、自定义 Marshaler。[]byte 的 base64 与结构体 omitempty 是显式排除边界。边界规范化操作局部 out，不覆盖内部 items。clear 不改变长度、nil 截短仍 nil、向 nil 追加零项仍 nil。

测试：模型单测覆盖 nil/空差异、append、clear、截短、规范化不丢元素、协议检查与旧输出失效；浏览器专属用例覆盖失败修复、回退、四类帮助与主实验隔离、答案揭示门槛、320/390px 和键盘。独立单测由本题执行；全量构建与浏览器由主代理统一执行。
