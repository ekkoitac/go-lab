# 第 132 题：乐观锁编辑台

依据用户《学习-知识点教学中的交互与呈现方式》设计，以双编辑者泳道、唯一数据库记录和 SQL 视图联动呈现并发因果。学习目标是区分版本展示与版本条件更新，解释影响 0 行，以及识别换版本号重试仍会覆盖旧字段。

操作：切换 CAS / 无条件覆盖及提交顺序（开启新轮）→ 两人读同一 v7 并编辑不同字段 → 第一人提交 → 提交第二次写入的行数预测与理由 → 执行并观察记录 → 选择重读合并 / 旧草稿换版本号重试。支持回退、重置；纯状态模型保留每次记录和草稿，提交写入与版本比较作为单次转移。

四种帮助分别是纸表类比、真实条件分支图、冲突处理核对步骤、新库存 30 → 40 情境预测。帮助练习不写入正式成绩或独立掌握记录。

边界：记录始终存在、语句执行成功，CAS 为原子教学模型；不证明真实数据库锁或隔离语义。两人改不同字段所以合并可定义；同字段需业务裁决。无条件模式仍递增版本，用于证明版本递增不等于版本保护。

验证：tests/database-lesson132.test.ts 覆盖两种提交顺序、丢更新、拒绝旧版本、正确重读合并、错误换版本号、输入不变性和迁移输入。CSS 限定 .db132，窄屏纵向泳道，原生键盘表单及焦点描边。
