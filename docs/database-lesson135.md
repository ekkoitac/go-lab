# 第135题：Outbox 崩溃窗口实验

- 学习目标：区分业务提交、持久化发送依据、broker 接收、发送标记、消费者效果；解释 Outbox 恢复与重复窗口。
- 呈现：持久化对象泳道、事件副本、积压与最老年龄、因果日志。交互：单步、预测累计投递次数和业务效果次数及理由、任意时刻崩溃/重启、等待、回退、配置对照。
- 直接双写提交后崩溃会失去内存发送意图；同事务 Outbox 保留待发记录。发送成功而标记前崩溃则重投同一 E-1；关闭消费幂等即可观察两次效果。
- 帮助 example：在相同崩溃点对照两种方案。diagram：真实原子边界、投递和确认关系，选择边界联动高亮。steps：依次运行并解释四步持久化证据。try：迁移到会员积分，构造重复与修复，不计正式成绩。
- 模型：单订单、单事件、可靠 broker 持久化、串行展示投递/消费；幂等记录与效果假定同一消费者本地事务。本模型不模拟 WAL、外部非原子副作用、网络分区、吞吐或 P99。Outbox 不保证端到端 exactly once。
- CSS 独立 db135 前缀，窄屏纵向泳道，所有控件支持键盘，具有可见焦点；窄帮助容器采用容器查询纵向重排，关系图在 500px 以下显示纵向关系图；390px 实际布局需由集成浏览器检查。
- 自动验证：`npx tsx --test tests/database-lesson135.test.ts` 覆盖丢消息、恢复、重复、幂等、积压年龄、不可变快照与回退；整体 TypeScript 检查交由主代理汇总。
