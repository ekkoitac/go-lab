# 154：容量、队列与期限

目标：解释速率、执行并发和队列容量是不同约束；从具体请求的等待和执行时间预测有效完成；用准入和协作取消修复长队列。

设计依据：用户指定《学习-知识点教学中的交互与呈现方式.md》。呈现为请求编号流图、指标和阶段事件；交互为调参、故障构造、单步/回退、同输入对照、图形关联和先预测后验证。

模型按整秒运行，每秒依次检查期限、准入、FIFO 调度、执行一秒。每个请求固定同质执行时间。预计完成由当前工作槽剩余耗时及 FIFO 队列计算；完成时间等于期限计有效。到期等待请求丢弃；在途请求只有启用协作取消才释放，否则继续执行并可能产生迟到完成与无用槽秒。队列峰值是请求数量而非真实内存字节；无用执行只计客户端到期后的执行，不把全部失败工作都算成无用。

基线每秒 4 请求、持续 4 秒、2 个槽、3 秒耗时、5 秒期限、容量 20：16 到达，有效 2、迟到 4、过期丢弃 10、无用 6 槽秒。只修改队列为 2、启用预计完成准入和协作取消后：有效 4、拒绝 12、无迟到/过期工作。不会将拒绝率等同整体业务质量。

四帮助：同流量终态对照；切换准入并关联 t=3s 的节点与编号；独立单步实验；缩略图新情境预测有效完成及理由，先锁定输入后揭晓，再换情境。辅助练习不写正式成绩。

边界：确定性耗时、无重试、无公平性模型、不推断生产吞吐。没有无界模拟选项，以有限的大队列体现长等待。

验证：tests/resilience-lesson154.test.ts 覆盖守恒、队列和并发上限、期限边界、取消与快照独立、速率/耗时差异。浏览器专属测试覆盖键盘、回退、修复、参数重启、390px 与 reduced-motion、四帮助及预测门槛。
