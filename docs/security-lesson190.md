# 第190题：审计证据装配台

依据用户《学习-知识点教学中的交互与呈现方式》：采用预测验证、参数操控、反事实干预、诊断修复与证据推理；呈现为业务时间线、事件卡、结构化编码视图联动。

学习目标：区分请求、授权拒绝、实际完成与保存成功；能指认缺失 actor/correlationId 或泄漏 Authorization/body；能解释事后审计失败不等于业务回滚。

动手观察：先选预测并输入理由，再单步收到请求、检查授权与前置策略、执行业务、受控调查。运行条件修改开始新预测，回退恢复旧条件及预测。用换行样本观察 JSON 编码保持事件边界；输入仅使用虚构教学数据，真实服务应限制备注自由文本。调查员权限及保留期控制记录可见性。

帮助：登记簿类比让学习者补可信编号、移除敏感附件；关联图让学习者断开 correlationId 并观察查询证据链丢失；步骤模式回放完成事件保存失败并显示业务仍导出120行；迁移模式预测不可逆转账早期或晚期审计故障。

边界：没有真实日志、秘密或业务；没有持久补记队列；显式继续策略仅展示风险取舍，不能自动保证补记成功。前置检查不能消除业务完成后写入失败，真实系统需一致性与持久补记协议。模型没有防篡改承诺，不把普通同机日志视为不可否认凭证。帮助练习与正式掌握记录隔离，理由仅展示自查，不声称自动评估自然语言推理。
