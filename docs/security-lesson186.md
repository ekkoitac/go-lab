# 186：密钥轮换的交互设计

依据用户指定《学习-知识点教学中的交互与呈现方式》：学习目标是解释验证集合、签发时刻、TTL/时钟容差如何共同决定票据接受结果。

- 动手观察：三实例识别集合 + 每票接受矩阵 + 事件时间线；先预测最新票的接受实例数与理由，再逐个发布、切签发、签票、推进时钟或撤旧。状态快照支持回退和从旧状态分叉。
- 误解反例：先切新签发造成未收敛实例拒绝；提前撤旧中断有效会话；签发者未切换时撤旧，后续旧票仍被拒；继续旧签发会推迟最晚撤旧点。
- 时间规则：最后旧签发 + 最长 TTL + 容差，时间达到边界即过期。主实验为分钟、TTL 6、容差 2。
- 诊断修复：逐个补新验证能力，观察同一张新票在矩阵中从拒绝转为接受；回退提前撤旧并等待窗口。
- 四种帮助：可操作售票/检票口类比；可增删新钥识别边的关系图；自主执行顺序的过程工作台；最后签发 t=4、可变 TTL 的下载链接迁移题。确认泄露改变处置目标，不能机械等待自然过期。
- 每个帮助实例都使用局部状态；未调用 progress、attempt 或 reveal。探索与独立课程作答隔离。
- 边界：仅符号 key ID，无真实密钥、网络或密码学运算；单签发者、配置立即到达所选实例，急停假定撤销信号全部收敛。现实需另外验证缓存、传播、签发端收敛与失败率。对称验证材料可能具备签发能力，非对称只需公钥。
- 键盘：原生 select、button、checkbox、range、textarea；可见焦点；320px 单列布局，表格使用固定列宽和换行，不含 SVG。
