# 第 136 题：Saga 取消工作台

## 教学目标与误解

学习者应区分外部资源状态、编排器确认状态和无法撤销的影响。实验暴露三种误解：发送取消就等于成功；超时等于失败；补偿等于数据库回滚。

## 交互与呈现

- 状态图、供应商资源卡、编排器待办、不可逆影响和步骤日志联动。
- 先填写下一步预测和理由，再单步执行，保留原预测并给出实际结果与因果提示。
- 可选持久化或仅内存。注入进程重启观察待办是否恢复，外部世界不随进程消失。
- 释放可明确失败、成功，或超时且已执行/未执行。未知结果必须先按同一业务键核对；失败两次转人工责任人。
- 回退只是教学快照回看；明确提示真实补偿不能倒带。重置开启新实验。

## 帮助

example 用旅行账本展示取消后的余留影响；diagram 选择故障分支追踪责任；steps 提供证据驱动诊断顺序；try 使用门票退款的新情境，先选策略和理由再检验，不写正式测验成绩。

## 边界与验证

教学假设供应商支持业务键幂等以及确定结果查询，重试次数 2 和手续费 3 元均为情境参数。现实还需执行意图先落盘，核对外部执行与结果记账之间的崩溃窗口，配置超期监控与人工运营；本实验不宣称跨库原子性。

纯模型测试覆盖不可逆副作用保留、持久化恢复、重试转人工、两种超时结果的核对、内存进度丢失和同键重放幂等。所有控制使用原生按钮/选择/文本框，CSS 限定 .s136，使用可换行布局支持窄屏。浏览器交互与 390px 实测由主代理集成后验证。

## 帮助模块复核改进

状态图使用实际 DOM 节点与带条件文字的箭头，三条路径分别展示失败重试、超时核对、重试预算耗尽转人工；选择路径同时高亮节点和箭头，并联动展示编排器认知与供应商实际资源。分步帮助通过模型生成 7 份证据快照，支持前进、后退与重新追踪，逐次展示资源、待办、重启次数和日志，覆盖两次重启与超时后核对。
