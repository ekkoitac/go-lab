# 第 37 题：先检查错误，再使用结果

| 设计项 | 实现 |
|---|---|
| 学习目标 | 根据 API 契约判断结果有效性；在第一次使用前检查；不混淆部分成功 |
| 典型误解 | 先访问再检查可补救；有 err 就必须丢弃全部返回数据 |
| 核心关系 | 返回协议、执行顺序、原始错误与调用者可见故障 |
| 动手观察 | 成功/失败输入；先检查/先使用/忽略错误策略；单步、回退、修复重跑 |
| 呈现形式 | 调用顺序与结果、原始错误、调用者输出三卡联动 |
| example | 同一返回值并排执行两种策略，成功样例与失败样例对照 |
| diagram | 可操作 Read 数据流：有效字节数、EOF/故障、消费策略、单步与关联卡 |
| steps | 分步检查可用性与不可达后续语句，支持回退 |
| try | 新连接故障中选择策略、提交预测与理由后验证 |
| 模型边界 | load 失败时返回 nil；Read 单次 ASCII 有效前缀可与错误并存 |
| 反馈 | 原始错误仍存在；nil 访问 panic 使正常错误返回不可达，未声称错误被删除 |
| 证据边界 | 辅助迁移不计成绩，理由自查，揭晓前不渲染答案状态 |
| 可访问性 | 浅色主题、原生键盘操作、aria-live、窄屏堆叠及 reduced-motion |
