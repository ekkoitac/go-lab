# 第33题：遍历边界与动态任务队列

依据《学习-知识点教学中的交互与呈现方式.md》，先定义学习目标，再配置呈现和操作。此模块不写入掌握成绩。

| 设计项 | 本题设计 |
|---|---|
| 学习目标 | 解释 range 初始边界与动态 len 条件差异，预测新增任务是否处理，并识别终止预算。 |
| 典型误解 | append 会扩展本次 range；range 深复制全部元素；下标递增就必然终止。 |
| 核心关系 | 游标、初始长度、当前长度、任务生成和终止条件间的因果。 |
| 呈现形式 | 同一初始任务和增长规则的双栏切片格子、游标、处理记录、当前操作反馈。 |
| 交互任务 | 构造0–4项初始任务；选择不增长、只初始项增长、持续增长；单步检查/处理/追加/前进；回退和重置；调整总任务上限。 |
| 模型反馈 | 不可变状态保存历史；每动作明确变化和下一动作。range 边界固定，队列边界随追加变化。上限拒绝追加，但继续消费已有任务。 |
| 帮助方式 | example：纸上点名与滚动报名册可操作类比；diagram：点选格子联动两个边界判断；steps：X发现X′的真实模型逐步执行和回退；try：报告产生复核任务的新情境，先提交两个数量和理由再验证。 |
| 独立验证 | 这里所有操作均属有帮助探索，不授予独立成绩；正式独立验证仍由既有课程测验承担。try 改变报告数或上限会清除已揭晓状态与旧预测。 |

## 语义边界

只模拟尾部追加与有限增长，不模拟切片容量、底层数组重分配、删除修改、map迭代。明确说明 range 并非深复制；只固定遍历所需切片值和初始长度。元素仍可能共享底层数据，不能从格子图推断存储地址。

预算是显式教学守卫，不是 Go 自动限制。持续增长模式在拒绝追加后才得以完成，真实应用还需任务增长策略、去重或预算。各通道只在自己的循环体内追加；range 退出后不继续产生任务，符合代码控制流。

## 可访问性与验证

按钮和表单均支持键盘与可见焦点；事件反馈通过 aria-live 宣告；当前游标同时提供文字与边框，追加项提供文字与虚线。双栏在窄屏变为单栏，控制组和任务格换行，reduced-motion 禁用动效。

纯模型测试覆盖：初始边界固定、动态子任务消费、追加独立步骤、不可变历史/回退重放、持续增长预算、空切片、无增长对照、预算拒绝、无效输入和迁移参数。
