# 第 140 题交互设计

目标：从同一请求的分段追踪与同一进程的 DB.Stats 窗口差分定位连接排队；区分累计、等待样本均值、请求 P99，理解扩池预算。

- 呈现：到达时连接槽、按持续时间比例显示的请求时间线、累计读数与窗口差分表。所有数值显式标记为确定性教学模型。
- 交互：逐步采集证据、回退、重置；切换 Rows 未关闭 / 长事务 / SQL 慢；关闭 Rows、缩短事务或优化 SQL；更改池上限和同时到达请求数。预测必须填理由，反馈不计分。
- 机制：基线 20 槽全部占用，4 个问题持有者，其余在 850ms 归还。Rows 修复释放 4 槽，事务修复在 30ms 释放 4 槽。有限槽处理 8 个同时到达请求时仍会出现第二波排队。扩池可绕开当前批次等待，但超出本应用 20 连接预算且未修复持有者。
- 帮助：example 是同输入 SQL 优化对照；diagram 展示资源依赖及时间关系，并以两条请求说明分段 P99 不可相加；steps 逐步收集并约束诊断证据；try 使用 SQL 慢/长事务新情境要求判断及理由，不写成绩。
- 边界：模型不模拟数据库真实过载速度，不用增加池大小自动制造虚假 SQL 延迟。数据库预算需要生产容量证据；InUse 高不能单独证明泄漏。计数跨重启下降应重建窗口。P99 使用有限教学样本最近秩，不能当生产尾延迟。

验证：`node --import tsx --test tests/database-lesson140.test.ts` 覆盖分段守恒、窗口差分、资源修复、批量排队、容量预算、计数重置及 P99 反例。
