# 144 · singleflight 的范围与时间边界

## 学习目标与形式

根据指定《学习-知识点教学中的交互与呈现方式》，采用参数操控、预测验证、关联探索、单步回退和反事实干预。呈现为实例网格、放大的 Group/key 调用卡片、两波时间线、指标以及租约状态图。

观察目标：同一进程内同一 Group 对象、同一 key、进行期间重叠的调用才能共享 fn 结果。完成后的下一波不保留结果；不同对象、key、进程彼此独立。

## 确定性模型

每波每个实例每个 Group/key 三次调用，均假定缓存初始为空且成功完成。默认 20 实例：首波 20 次 fn、40 名等待者，第二波结束累计 40 次。Group/key 翻倍增加独立工作；串行到达则每组合三次执行。串行模式首步只启动首个调用，完成步内依次执行其余两个。

可选共享缓存仅在首波全部结束后命中第二波；不把缓存命中归因于 singleflight。未模拟 Forget、错误传播、取消、压测或缓存过期。主模型不使用分布式锁。

租约帮助是独立简化模型：A 获得令牌 1，租约过期后 B 获得 2；B 新值先提交，A 旧值后提交。启用存储端 fencing 拒绝旧写入，但查询次数仍为 2。假定单调令牌与写入端校验，并不声称 exactly once。

## 四种帮助

- example：窗口登记簿类比，增开独立 Group、改变到达时机，改变调用卡片和工作量。
- diagram：20 实例地图，选实例放大 Group 与执行/等待者，切换 key 数反映全局回源数量。
- steps：租约到期、B 提交、A 晚到的单步状态推演；fencing 可反事实切换，支持回退和重置。
- try：双实例首波预算 2，选择重叠/串行和缓存条件，提交两波次数预测及理由后验证。只作辅助练习。

所有状态只在组件局部，不修改得分或独立掌握记录。调整主实验条件会清除预测，回退保留原预测便于比较。

## UI 验证路径

主根 `cache-message-lab-144`，帮助根 `cache-message-help-144`；各有 `live-model` + `data-state`。

1. 默认填“预测回源次数”40，“我的依据”填写理由，点“提交预测并发出首波”：origin=20，waiting=40；点击“实例 20”展开内部三调用。
2. 点“完成首波”→“发出第二波”→“完成第二波”：origin=40，returned=120，反馈“预测吻合”。
3. “回退一步”退到第二波进行中；“重置实验”恢复全部默认。
4. 将“实例数量”改为1、“每实例的 Group”改为2、“每 Group 的 key”改为2，预测8次完成：同实例不同 Group/key 不合并。
5. 改“同组合的 3 次调用”为“前次完成后再到达”，默认20实例预测120次：观察首步只有20执行、没有等待者，首波完60，两波完120。
6. 勾“首波完成后写共享缓存”，默认20实例预测20次，第二波直接命中60调用；不是跨进程合并。
7. 帮助 steps 连点“推进租约事件”三次显示“A 的旧值”；勾“写入端校验 fencing 令牌”变“B 的新值”，仍两次查询。
8. 帮助 try 填“预测两波回源次数”4和理由，点“验证我的方案”，显示双实例首波2、两波4；串行方案超预算。

布局采用容器查询，20节点自动换行，窄帮助栏单列；所有操作为原生按钮/表单，焦点可见，状态反馈 aria-live，支持 reduced-motion。

## 核对与测试

Go 官方 [singleflight 文档](https://pkg.go.dev/golang.org/x/sync/singleflight) 的 Group 与 Do 定义用于核对命名空间、进行中的同 key 调用共享及完成结果传播；本模型未覆盖 Forget 等额外 API。
