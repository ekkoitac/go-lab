# 第 143 题：缓存过期调度台

学习目标：区分多 key 同步失效与单 key 并发击穿，解释 TTL 抖动、同 key 合并、回源准入各自影响的环节。依据用户指定《学习-知识点教学中的交互与呈现方式》，用过期桶、请求因果链与数据库槽位做多视图联动；操作包含调参、对照、先预测并说明理由、单步、回退与边界反例。

模型缩为 12 个请求。每个 key 在过期瞬间收到一次并发请求批次；查询在下个 10 秒窗口前完成。哈希映射到业务允许的 300–360 秒离散窗口，单 key 共享同一过期时刻。数据库安全容量固定 4，准入预算可调，超额直接拒绝，没有队列、重试、缓存再填充、真实吞吐或延迟模拟。过载表示超容量查询计数，不虚构线上性能测量，也不验证缓存一致性。允许区间缩到零可验证抖动失效；预算大于安全容量也会过载。

四种帮助：example 用餐桌取餐场景切换多 key/单 key；diagram 拨动保护开关并同步更新流程图；steps 逐窗口跟踪确定性回源和拒绝；try 按“安全且零拒绝”双目标修复配置并解释原因后验证。帮助属于有提示探索，与课程得分隔离。

UI 验证准备：进入 143 题动手观察，先填预测与理由，然后逐步走到 360 秒；试抖动、热 key、合并和不同回源名额；回退、重新预测、恢复默认。四帮助分别检查交互，窄栏与 390px 检查过期桶换行和无横向溢出。根 cache-message-lab-143，帮助 cache-message-help-143，live-model 的 data-state 提供当前配置、游标和窗口结果；关键动作 data-cm-action=step/back/reset。
