# 第 194 题交互实现

学习目标：解释 expand / migrate / contract 的兼容边界，能用行版本证据判断回填是否覆盖并发写入，识别后台任务及回滚版本也是旧列读者。

## 动手观察

- 默认单步：新增字段 → 事务兼容写 → 本人确认姓名映射 → 读取批次 → 条件回填 → 核验 → 新读切换 → 审计旧 API 和后台任务 → 结束回滚窗口 → 收缩。
- 每次动作都产生可回退快照；重置还原初态。所有操作和拒绝原因显示在状态区。
- 并发故障：前三步后点击“读取回填批次”“插入并发改名”“无版本保护回填”“核验当前数据”。用户 1 的旧列为王小敏，新列回退成小明，来源 v1 落后于当前 v2。重新读取、安全回填并核验可修复。
- 安全对照：同样并发过程，改用“按版本安全回填”跳过过期快照，保留事务写入的新版姓名。
- 任意时候“尝试删除旧列”显示尚未满足的真实门槛。
- 姓名不机械拆分。王小明、王小敏的映射来自预设产品规则；Madonna 必须确认单名规则，family_name 才可使用空字符串。

## 换个方式理解

- example：固定第二次写故障，切换本地事务/两次独立写，比较新旧邮箱列是否一致；事务回滚仍明确请求失败。
- diagram：可探索 SVG 依赖图，切换读者和删除旧列，直接观察旧 API、后台任务、回滚版本失去读取依赖。
- steps：v7 回填快照与 v8 在线写的四步并发时间线，展示条件更新拒绝及重读。
- try：HTTP 全升级但周报仍依赖旧列、48 小时窗口仅过去 6 小时的新情境，先选择并写理由再揭晓；答案后的重试明确标注，不持久化掌握成绩。
