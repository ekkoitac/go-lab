# 第 51–60 题：按知识关系设计的交互实验

依据：`E:\ekko-lib\ekko-lib\临时\学习-知识点教学中的交互与呈现方式.md`。

呈现形式、交互方式与学习目标分开设计。每题由一个独立 subagent 实现，主代理负责入口、共同样式、跨题回归与最终集成。既有编辑器、题目、独立掌握规则和持久化接口保留。

| 题号 | 学习目标与典型误解 | 呈现与操作 | 必须看见的因果证据 |
|---|---|---|---|
| 51 | 通信完成不等于业务完成 | 双方执行位置、无缓冲交接；安排角色执行 | 同一任务卡在发送；独立接收使交接完成，业务仍待处理 |
| 52 | 缓冲只能吸收短时积压 | FIFO 槽位、发送者待发值、容量控制 | 满队列阻塞，消费释放位置，待发值进入队列 |
| 53 | 关闭责任必须有生命周期依据 | 双生产者与协调者；排列发送、Done、Wait、close | 全部发送者完成才可安全关闭；早关后发送 panic |
| 54 | 零值与结束不能只看 value | 缓冲格、接收记录与 value/ok 联动 | 关闭保留数据，0/true 与排空后的 0/false 不同 |
| 55 | nil 禁用分支，关闭仍就绪 | 通道引用和分支状态；断开输入并测试退出 | closed 重复就绪，nil 无通信对象，全部 nil 需要退出条件 |
| 56 | case 顺序不产生优先级 | 就绪集合、选择路径、消息保留 | 一次选择一个分支，未选消息保留，随机与演示分开 |
| 57 | 非阻塞试探不等于免费等待 | 对照循环计数与等待状态 | default 反复执行；无 default 等待事件；消息/取消可唤醒 |
| 58 | 取消是通知，不是强制退出 | 父子任务、Done、清理与确认 | 通知、观察、清理、退出是不同事件 |
| 59 | 缓冲不替代管道回收 | 上下游与阻塞发送、取消出口 | 下游退出后发送仍可阻塞，监听取消且等待 done 才完成回收 |
| 60 | 执行上限与排队上限不同 | worker 工位、jobs 队列、结果顺序 | 活跃数受 worker 数限制；队列空不代表完成；需要统一收尾 |
