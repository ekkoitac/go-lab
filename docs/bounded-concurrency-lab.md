# 第 121 题：执行有界，等待在哪里

第 121 题「动手观察」现在加载独立并发实验台，其他学习阶段及真实 Go 编辑器保持原来的行为。实验状态仅驻留内存，不写入题目成绩、进度或备份；题目 ID、版本、答案、源码不变。

## 四段学习路径

1. **观察突增**：同一批 8 项任务，对照直接启动与固定 worker。预算 2 仅作超限判断，直接启动仍会执行 8 项。
2. **验证误解**：对照 goroutine 内获取许可与固定 worker；预测执行峰值和工作 goroutine 峰值。点击 T3 同时追踪两侧的位置、代码和事件。
3. **缩小队列**：容量 6 改为 2，观察 2 项执行、2 项缓冲、4 项尚未接纳；容量 0 展示直接交接。
4. **修复与复验**：完成 8 项，同时使执行、工作 goroutine、缓冲队列峰值均不超过 2。失败项可定位首次超限；通过后同配置运行 16 项。1 个 worker 等较慢但满足约束的配置也可通过。

## 模型规则

- 三种策略共享配置和逻辑时钟。每项耗时 2 个模拟时间单位，FIFO 作为本模型的确定性调度；不声称 Go 调度保证或生产性能预测。
- 首次提交时为 t=0；之后每步推进 1 单位。同一时刻先完成所有到期任务，再分派任务。结束较早的面板保持完成状态。
- 直接启动：全部任务立即执行；goroutine 内限流：全部创建，再按许可数量执行，其余等待；固定 worker：先让空闲 worker 接手，再填充有限缓冲，余项留在原始批任务列表。
- 单一生产者被背压阻塞，不为尚未接纳的任务创建 goroutine。批任务列表仍然占资源，有界缓冲不代表入口或系统内存已经有界。
- worker 数为 `min(limit,total)`。已提交全部任务后关闭队列，空闲 worker 退出，忙碌 worker 完成最后任务再退出。工作 goroutine 数不包含图中单列的协调者。
- 工作 goroutine 的创建/完成、队列领取等被合并为逻辑边界快照；代码高亮表示任务关联操作，不是 Go 调试器的真实执行行。教学片段省略统一等待收尾。
- 历史为完整快照，回看不重新调度；前进重放已有历史。调参、切换阶段/策略会暂停并重建本轮。播放需显式启动，系统减少动态效果时关闭卡片入场动画。
- 所有计数、泳道、时间条、代码关联及挑战结果由同一状态生成。挑战通过必须运行至完成，不能凭尚未出现超限的初始状态通过。
