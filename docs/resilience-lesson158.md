# 158：协调退出的依赖顺序

依据用户指定《学习-知识点教学中的交互与呈现方式》，用「排序构建 + 单步执行 + 诊断修复 + 预测验证」，呈现为退出操作序列、HTTP/后台/资源泳道和事件证据。

- 学习目标：解释撤就绪、停止接收、HTTP 排空、取消通知、后台回收和资源关闭的关系；识别硬期限内无法完成的工作。
- 动手观察：每一步可选择操作，等待步骤依实际状态持续执行。注入先关库故障会产生请求失败和后台资源后用故障，修复脚本重跑，对照失败/完成计数。支持精确回退和重置。
- 举例子：餐厅订单与盘点员类比，同条件同步推进早关资源/协调退出，失败与完成直接可见。
- 画图：选择 HTTP、后台或资源泳道后，直接对该生命周期施加动作，依赖边对应状态高亮。
- 拆步骤：从错误脚本起步，事件证据定位原因，再调整步骤并验证。
- 让我试试：HTTP 已排空的新情境，先选择结局并填写理由，才能运行；第二情境改变清理时间和退出预算。帮助独立状态，不写进度/正式成绩。

模型每个非退出动作推进一秒，每秒完成一个在途请求，取消后需额外清理时间；Shutdown 不回收自建后台，wait 不代替 cancel。硬期限到达仅记录未完成，恢复仍需要外部持久化核对。可手动注入两个到达请求：只撤就绪时模拟迟到流量继续接入，Shutdown 停止监听后拒绝接入；协调完成必须验证撤就绪和停监听。模型不模拟真实流量传播时长与升级连接，不作为真实关闭耗时依据。

验证：专属模型单测覆盖正确顺序、资源后用、取消与等待分离、Shutdown 边界、硬期限、错误等待、立即退出和历史不可变。浏览器用例覆盖故障/修复/回退与四帮助，390px、减少动画、预测门槛和正式成绩写入隔离。
