# 第 38 题：错误包装与身份

| 设计项 | 实现 |
| --- | --- |
| 学习目标 | 以 Unwrap 可达性、对象身份与类型匹配分别解释 errors.Is/As，区分可读文案与机器协议。 |
| 典型误解 | %v 保留了文本就能找到根因；外层 %w 能修复中间断链；同文案的新错误等于原错误。 |
| 核心关系 | 错误对象身份、单向引用链、逐层查找、结构化类型。 |
| 呈现形式 | 从外层到根因的关系图、代码、检查路径、As 字段提取。 |
| 交互任务 | 构造 1–3 层、编辑上下文、切换 %w/%v、选择普通/结构化根因、切换查找目标、单步回退重置。 |
| 模型与反馈 | %w 保存 cause；%v 保存完整文本但 cause=null；Is 比较目标身份，As 匹配 StockError 并提取 SKU/Missing；检查一层给出继续/停止原因。 |
| 帮助方式 | example 比较订单前缀导致的字符串检查失效与身份检查；diagram 选择对象并修复中间断链；steps 双层可回退追踪；try 两个新情境先预测 Is/As 加理由再验证。 |
| 独立验证 | 带帮助练习不写入独立掌握；理由供对照证据自查，不声称自动评分。 |

模型只含单链、直接身份相等、StockError 类型匹配；不模拟自定义 Is/As 和 errors.Join 多分支。普通根因是 errors.New 生成的对象；结构化根因是实现 Error 的 *StockError，携带 SKU/Missing，Error 返回 no stock。图保留断链以下的原对象用于解释，但查找绝不跳过断链。

上下文只当作 fmt.Errorf 的 %s 参数，用户输入的百分号不会被误当格式占位。是否暴露底层错误身份是公共契约，不应一律把所有错误改成 %w。

专项测试：node --import tsx --test tests/control-flow-lesson38.test.ts。覆盖同文案不同连接、内层断链、同文案不同身份、类型提取、未完成状态/回退、上下文与输入范围。
